JWT REGISTER ERROR FIX (Illegal base64 character '-')

Root cause
- In JwtService.java, getSigningKey() decodes app.jwt.secret using Base64:
  Decoders.BASE64.decode(jwtSecret)
- Your configured secret is not valid Base64 (often a UUID or plain text with '-' characters), so token generation fails at register.

Where it fails
- spring-boot-modules/authManagement/JwtService.java
  private SecretKey getSigningKey() {
      byte[] keyBytes = Decoders.BASE64.decode(jwtSecret);
      return Keys.hmacShaKeyFor(keyBytes);
  }

Fix
1) Set app.jwt.secret to a valid Base64 value with at least 32 raw bytes.
2) Restart the Spring Boot service.
3) Retry register.

Example config
- File: spring-boot-modules/authManagement/application-security.properties (or your active profile properties)

app.jwt.secret=VGhpc0lzQVN0cm9uZ0Rldk9ubHlCYXNlNjRTZWNyZXRLZXlGb3JKV1QxMjM0NTY3ODkw
app.jwt.expiration-ms=86400000

Generate a strong Base64 secret (PowerShell)
- Run this command and copy the output to app.jwt.secret:

[Convert]::ToBase64String((1..64 | ForEach-Object { [byte](Get-Random -Minimum 0 -Maximum 256) }))

Important notes
- Do NOT use plain text like: my-secret-key or UUID strings with hyphens.
- Do NOT wrap the secret with quotes unless your parser requires it.
- Ensure there are no leading/trailing spaces in app.jwt.secret.

Optional hardening
- Add validation at startup to fail fast with a clear message if app.jwt.secret is not valid Base64 or too short.
