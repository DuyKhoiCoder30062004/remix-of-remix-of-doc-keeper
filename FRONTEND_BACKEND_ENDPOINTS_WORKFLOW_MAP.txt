4) FULL APP WORKFLOW (END-TO-END)
============================================================

A) Authentication flow
1. User opens auth page: src/routes/auth.tsx.
2. Frontend calls authApi.login/register in src/lib/api/auth.ts.
3. Token is stored via setAuthToken in src/lib/api/client.ts.
4. use-auth hook loads current user via /auth/me and protects private routes.

B) Dashboard listing flow
1. Dashboard page src/routes/index.tsx loads documents list.
2. Frontend calls documentsApi.list from src/lib/api/documents.ts.
3. Table renders title, type, size, owner, and updated date.
4. Client-side filters are applied on frontend only:
   - file type category filter
   - newest-to-oldest or oldest-to-newest sort

C) Upload flow
1. Upload page src/routes/upload.tsx accepts file + optional folder.
2. Frontend builds multipart payload in documentsApi.upload.
3. Backend stores file_data/content_type/metadata and returns document.
4. Frontend invalidates documents queries and list refreshes.

D) Folder management flow
1. Folders page src/routes/folders.tsx loads folders and documents.
2. Create/rename/delete folder uses foldersApi create/patch/delete.
3. Move document uses documentsApi.move(docId, folder_id).
4. Same frontend-side filtering/sorting is applied in folder document pane.

E) Document details + permissions flow
1. Detail page src/routes/documents-id.tsx loads one document.
2. Reads current ACL via permissionsApi.listForDocument.
3. Owner/admin can grant/update/revoke access using permissionsApi.
4. Audit log loads via documentsApi.auditLog.

F) Sharing request flow
1. User submits sharing request via sharingApi.request.
2. Backend stores request with permission + status.
3. Recipient view in src/routes/sharing-requests.tsx shows incoming requests.
4. Recipient approves/rejects via sharingApi.approve/reject.
5. Backend updates status and (on approve) permission record.

G) Admin operations flow
1. Admin page src/routes/admin.tsx uses usersApi and management actions.
2. Admin can review user state and sharing log visibility.
3. Admin-level endpoints enforce privileged actions.

H) Data and schema workflow
1. Seed data files populate users/folders/documents/permissions/sharing_requests.
2. FK order must be parent first: users -> folders/documents -> permissions/sharing_requests.
3. RDS schema must match local defaults/constraints for stable insert behavior.
